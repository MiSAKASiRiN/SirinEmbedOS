# IMU调平与正常退出受控落座（2026-10-10）

revision17上电只回位、静止调平、保持，不自动旋转。350/4764/5070是接近水平的启动种子，其中ID1保留旧航向参考；ID2/ID3最终home由双IMU归一化重力方向平均确定。先按固定映射转换为板坐标，以200ms低通和静止1.5秒平均得到倾角；每次最多1°修正，平均重力偏离板+Z小于约0.25°后保持。双IMU差异超过3°、无有效采样、不能收敛等不继续追逐目标；90秒后LevelHold保持。真实水平仍受两颗加速度计未校准的零偏/尺度误差影响，不能宣称计量精度。

正常运行ID3仍严格保持4200→跨零→2160，首次恢复规则保持。用户明确授权正常退出专用越界到机械支撑：0x40/1改为受控降落请求，绝不直接设置inhibit。ID1/2保持当前位置，ID3使用-3°/s下降目标、重力前馈+速度PI（500/150）制动，输出只允许0..30000；加制动斜率40000raw/s、减支持8000raw/s。退出通道下界4000，上界不变。raw4000..4090附近位移/速度持续稳定1.5秒视为候选支撑，2秒逐步卸力并观察0.5秒；下降速度重新超过1.5°/s则恢复制动。确认静止后全部电机零输出。未在120秒内抵达支撑则LandingHold继续保持，不以超时直接清零。接触判据是编码器推断，不是力传感器确认。

phase21调平、22调平未确认保持、32正常降落、33卸力、34已落座零输出、35降落未完成保持；phase9为调平后保持。故障/反馈失联/时序看门狗的独立归零不被正常退出旁路，断电/MCU停止/CAN失联不能保证电阻尼。必须在MCU仍运行且有反馈时完成正常退出，再退出固件或断电。

capture.py默认在Hold记录6秒后请求降落，--stop等待落座确认；--keep-holding显式保留通电保持。Ctrl+C/SIGTERM在正常采集循环内请求降落并继续等待，串口异常只能尽力请求且报告未确认；SIGKILL、主机断电不保证发送。低于revision17拒绝使用新受控停止语义，避免误向旧固件发送立即归零命令。

修改位于示例控制、应用接入、主机采集与针对性测试；没有改SDK公共API、HAL生成代码、线程数量/优先级。新增少量静态滤波/状态数据，D1总量279776B。增量构建与停止/限位/调平方向针对性检查通过，无完整主机矩阵或虚拟植物测试。首次升级前用户确认已托住ID3，避免旧固件复位时直接落下。板端结果及后续修订见下文。
