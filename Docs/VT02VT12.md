# VT02/VT12 双向 UART 接入

本指南面向机器人 MCU，通过 VT02 发送端的 GH 串口与 VT12 选手端收发数据。SDK 公共名称使用 `VT02`，对应直接连到 MCU 的设备；覆盖 VT02/VT12 这一对图传。VT12 的 USB、视频解码、配对、信道和激活由选手端程序处理。

| 方向（以 MCU 为准） | 通路 | SDK 接口 |
|---|---|---|
| RX 键鼠 | 选手端 → VT12 → VT02 TX → MCU RX | `SRNOS_InputFind("vt02")`、`SRNOS_InputReadSnapshot` / `SRNOS_InputReadEvent` |
| RX 自定义 | 同上，`0x0302`、30 B | `SRNOS_MESSAGE_VT02` 的 Message 路由 |
| TX 自定义/业务帧 | MCU TX → VT02 RX → VT12 → 选手端 | `SRNOS_VT02Send`、`SRNOS_VT02Flush` |

两端共地，串口 **115200、8N1、非反相、双线全双工**。具体连接器针脚、电平和供电按对应设备手册及实物核对。SDK 不进行键鼠到运动的映射。

## 配置与完整示例

完整可编译应用见 [VT02VT12 示例](../Examples/VT02VT12/README.md)。父项目沿用 [QuickStart](../QuickStart.md) 的接入方式；以下为 `SRNOS_ApplicationConfigure` 内的配置片段，其余项使用 SDK 默认值：

```c
config->serial_count = 1;
config->serial[0] = (SRNOS_SerialConfig){
    .port = SRNOS_SERIAL_UART9, .baud_rate = 115200,
    .data_bits = 8, .stop_bits = 1, .parity = SRNOS_SERIAL_PARITY_NONE,
    .mode = SRNOS_SERIAL_DUPLEX, .rx_enabled = true, .tx_enabled = true
};
config->remote.vt02_port = SRNOS_SERIAL_UART9;
config->remote.vt03_port = SRNOS_SERIAL_NONE;
config->remote.video_link_enabled = false;
```

仅接收时设 `tx_enabled=false`。同一端口不能再绑定 `referee_port`、日志、Message UART、VT03、W.Bus、DR16 或应用自建 Serial 所有者。配置和路由在启动期冻结；运行期不能切换或重新 Init/Poll 内置端口。

## 接收键鼠

包含 `SirinEmbedOS/Services/Input.h`，从应用任务读取一致快照：

```c
SRNOS_InputSnapshot input;
if (SRNOS_InputReadSnapshot(SRNOS_InputFind("vt02"), &input) == SRNOS_INPUT_OK
        && input.online) {
    const uint64_t mask = SRNOS_INPUT_BUTTON_MASK(SRNOS_INPUT_KEY_W);
    bool w_pressed = (input.buttons_valid & mask) && (input.buttons & mask);
    /* 使用 w_pressed；业务动作、授权及更严格的时效由应用实现。 */
    (void)w_pressed;
}
```

键盘低 16 位依次为 `W S A D Shift Ctrl Q E R F G Z X C V B`；位 16/17 为鼠标左/右键。检查 `online` 和相应有效位；默认离线期限为 `remote.offline_ms=300` 毫秒。此来源没有模拟通道、拨轮或档位，不产生使能请求。

鼠标 xyz 是逐包相对增量，SDK 累计到 `relative_total[3]`（模 2³²），不能每次读取快照都再次应用同一个值。读者保存上一快照，检查 `relative_valid`、`relative_ms`，对同一 `epoch` 做模差；首次读取或 epoch 变化只建立基准。需要逐帧按键边沿时使用独立的 `SRNOS_InputReadEvent` 游标，处理 `SYNC` 和 `OVERRUN`。

## 接收自定义数据

包含 `SirinEmbedOS/Services/Message.h` 和 `SirinEmbedOS/Services/RemoteControl/VT02/VT02.h`。静态保存 route，在 `bind_channels` 回调注册并检查结果：

```c
static SRNOS_MessageRoute custom_route;
static bool bind(void *user)
{
    (void)user;
    const SRNOS_MessageRouteConfig route = {
        .transports = SRNOS_MESSAGE_VT02, .endpoint = SRNOS_SERIAL_UART9,
        .service = SRNOS_VT02_CUSTOM_SERVICE,
        .type = SRNOS_VT02_CUSTOM_MESSAGE,
        .max_payload = SRNOS_VT02_CUSTOM_LENGTH,
        .max_age_ms = 1000, .depth = 4, .policy = SRNOS_MESSAGE_FIFO
    };
    return SRNOS_MessageRegister(&route, &custom_route) == SRNOS_MESSAGE_OK;
}
/* 配置回调内：config->bind_channels = bind; */
```

应用任务使用 `SRNOS_MessageReceive(custom_route, &info, payload, sizeof(payload))`，其中 `payload` 为 30 B 数组。内容原样复制，无 SM/SirinRMT 外壳；`info.sequence` 为 A5 的 8 位包号，`received_ms` 为本机出队时刻，不是发送时间。该流量不刷新键鼠时效。

FIFO 用于有序事件；LATEST/depth=1 用于只关心最新值的场景。每个邮箱由一个任务消费，多个订阅者分别注册路由。用 `SRNOS_MessageGetStats` 检查覆盖、过期、丢弃。`SRNOS_MessageSend` 不支持 VT02 目的端，发送使用下述入口。

## 显式发送

下面是应用任务内的调用片段；`payload[30]` 和 `sequence` 由应用准备。没有启动发送、周期发送、自动应答或重试：

```c
SRNOS_SerialStatus write_status = SRNOS_VT02Send(
    0x0309, payload, 30, sequence, 200);
SRNOS_SerialStatus flush_status = write_status == SRNOS_SERIAL_OK
    ? SRNOS_VT02Flush(200) : write_status;
```

Send 将载荷封装为完整 A5 包并复制到既有 Serial TX 队列，返回后调用者可复用载荷。载荷范围 0～300 B，空载荷允许 NULL；命令和 8 位序号由应用指定。具体图传固件对命令和长度的支持需要单独确认，通用编码器不意味着任意内容都能无线透传。

`SRNOS_SERIAL_OK` 对 Send 仅表示入队，对 Flush 表示端口队列排空且 UART TC 完成；均不证明选手端收到。Flush 会报告既有 TX 错误。参数不合法返回 ARGUMENT，未启用 TX、未启动或不在任务上下文返回 STATE，锁/队列/排空等待可返回 TIMEOUT。超时采用 Serial 的毫秒合同，每次调用各有独立预算；超时或错误不能撤回已发送数据，重试可能重复投递。

应用应指定一个发送任务维持顺序；并发 Send/Flush 不构成原子事务，Flush 观察的是共享端口。Send 使用 309 B 局部包缓冲和 Serial 的嵌套复制，发送任务应留足栈（示例建议至少 2 KiB，并在实机检查水位）。SDK 不创建额外发送任务。

## 线格式、恢复和边界

MCU 侧业务格式为 `A5 | payload_length:u16LE | sequence:u8 | CRC8 | command:u16LE | payload | CRC16:u16LE`。CRC8 初值 `0xFF`、反射多项式 `0x8C`，覆盖前 4 B；CRC16 初值 `0xFFFF`、反射多项式 `0x8408`，覆盖尾部 CRC 之前的全部字节。键鼠 `0304` 为 12 B 载荷/21 B 整帧，自定义 `0302` 为 30 B/39 B。协议依据和独立 Framer/Poll 接口见 [模块说明](../Source/Services/RemoteControl/VT02/README.md)。

只有 CRC 有效且命令/长度匹配的 `0304`、`0302` 会分别投递为 Input/Message；其他有效命令跳过。UART 错误、恢复、溢出和读失败清除流状态，半帧超过 30 ms 没有读到新字节后丢弃。可用 `SRNOS_SerialGetPortStats` 观察已被内置协议占用的串口，无需取得其句柄或消费 RX。

内置接收复用 InputIO（优先级 47、栈 3072 B），每轮最多读取 1024 B；不新增线程。新增路由与串口队列按系统 heap 预算检查。不能用串口写成功、无线绿灯或网络 ping 替代原始载荷、序号及 CRC 的端到端验证；硬件改动后还应复测双向数据、输入释放和错误计数。

SDK 只负责 MCU 侧协议与资源合同。选手端 USB/DUML 包装、设备接线、固件镜像、操作过程和实机原始记录由父项目保管，避免将具体设备现场混入 SDK。硬件兼容性及验证范围见 [CHANGELOG](../Source/Services/RemoteControl/VT02/CHANGELOG.md)。
