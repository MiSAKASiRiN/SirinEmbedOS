# Studio转台校准 / recipe 0x54544332

上电旁路动作，CAN反馈/零命令、INS和60°C温控运行。Studio确认专用固件协议后，点击按钮启动：双IMU健康、温控反馈在目标±1°C内持续5秒（最多等待360秒），随后原直接位置/速度环回默认种子。不会开启虚拟轨迹。

12个静态姿态：ID1参考不变，ID2相对home为0/90/180/270°，ID3分别−30/+50/+150°；每次到位12raw/2°每秒内持续1秒，再静止采样2秒。先回home，再动态分轴：ID1/2各+180°往返、ID3+120°往返用于拟合；ID1/2各−120°往返、ID3+60°往返用于独立校验。每段从前一静止位置积分原始陀螺，参考角度使用真实编码器位移；静止段估计偏置。最后以任务号为种子的伪随机三轴目标连续改变3次，每段5秒，ID3目标始终内缩至合法弧段；回home后等待求解和写入。ID1/2可多圈，ID3运行限位4200→跨零→2160和启动恢复规则保留。

板端只采集原始SI统计/积分，不以已有INS结果充当真值。24条记录保存在板内，Studio用12个重力模约束拟合对角加速度偏置/比例，用6段旋转积分范数与编码器角度拟合陀螺对角比例，另外6段独立校验。静态重力RMS需≤0.015g、峰值≤0.04g，动态独立验证≤3%，温度跨度≤3°C，采样完整性和系数范围全部通过才保存。无跨轴矩阵、温度曲线或绝对航向校准；动态精度仍受编码器角度、轴机械非理想和同步误差限制。

Studio显示温度、阶段、进度、三轴实际/目标角、记录数量、拟合残差、保存掩码及EEPROM revision，3D模型/INS曲线继续运行。主机求解记录保存到Qt应用数据目录turntable。原始记录与结果在保存前可复核；连接中断、传感器失效、超时或质量失败不宣称成功。每颗IMU各自CRC/读回保存，部分保存明确显示，不能声称双记录原子。新值下次启动生效，不自动重启承重系统。

正常取消/5秒主机心跳超时停止推进并保持当前位置；反馈失联/电机原有故障/时序看门狗仍按独立故障归零。断电、暂停MCU或CAN失效不能保证承重。完成后保持供电，安全支撑后才复位或断电。旧固定输出下放不被本流程调用。

## 项目HostLink协议

service0x40/message2单路复用，首字节op，所有u32/float32显式小端。0查询能力/状态，1启动（u32任务号+u32配方签名），2查询状态并心跳（u32任务号），3读取记录（u32任务号+u32索引），4保存（u32任务号+两组13个float），5取消保持（u32任务号）。启动不会自动重发；相同任务号不能重启。状态体88字节`<9I9f4I>`；记录100字节`<2I23f>`。具体字段顺序以calibration_job.hpp及插件turntable.py交叉测试为准。保存仅接受当前任务Result状态且24条记录齐全，延后到HostCmd写EEPROM，不阻塞1ms控制。返回5个u32为saved_mask、两个StorageStatus、两个revision；错误/超时不自动重试，查询最终状态。service0x40/message1旧停止命令在本版本也只请求取消保持。

应用仍一个1ms周期线程/3072字节栈；在同线程推进任务和采样统计，使用约3KiB静态记录，通信与控制间使用有界原子快照。校准EEPROM工作复用 HostCmd，不另建线程。

## 主机打包示例

以下只生成查询能力请求正文，不打开串口、不启动运动：

```python
import struct
query_payload = struct.pack("<B", 0)  # service 0x40 / message 2 的正文
status_format = "<9I9f4I"
assert struct.calcsize(status_format) == 88
```

完整帧仍由 HostLink 编解码器封装并校验应答；不要把正文直接发送为串口帧。物理全流程、系数精度及每次修改的验证结果见 [CHANGELOG](CHANGELOG.md)，模拟数据拟合不能替代实机标定。
