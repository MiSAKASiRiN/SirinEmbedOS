# 固定 SPI4 通路

公开头为 `SirinEmbedOS/IO/SPI/SPI.h`。父项目使用 `SRNOS_*` 传输、取消与快照接口，不需要 HAL、FreeRTOS 或 CMSIS 头。`SRNOS_SPIDevice` 是不透明的 SDK 设备句柄；固定 CS、模式与设备绑定由 Board/设备驱动持有。父项目不能重建 SPI4 或直接控制片选。统计返回调用者拥有的副本。

## 调度与所有权

唯一 `SRNOS_SPI4` 分发线程保持 High6 / 3 KiB，负责 HAL、DMA staging、完成复制、回调及恢复。四个 IMU 槽和四个普通槽固定分配，类内 FIFO；有普通请求等待时，最多连续启动四个 IMU 请求。正在传输的事务不被抢占；没有运行期分配。

提交方在短临界区保留槽位（`RESERVED`），在保护范围外复制最多 512 B TX，再发布排队状态并通知分发者。复制期间，其他提交不能复用该槽，取消不能提前释放其所有权；`SRNOS_SPIIsBusBusy` 包含这些尚未发布的请求。TX 在提交返回后可以复用，RX 必须保留到完成回调或取消确认。所有传输使用 SDK 非缓存 staging，不公开 Direct 或原始 bus lock 入口。

超时使用 SDK 毫秒和公开头直接提供的 `SRNOS_NO_WAIT` / `SRNOS_WAIT_FOREVER`，有限正值为 `1..INT32_MAX`。所有 SPI DMA 都需分发线程启动，所以显式 `SRNOS_NO_WAIT` 立即返回 `TIMEOUT`，不提交、不等待，也不取得缓冲区所有权。无超时参数的 `TransferAsync` / `TransferDMA` 显式使用默认 5 ms 排队期限，调用本身仍只复制提交，不等待完成。

IMU 排队期限保持 1 ms；普通请求的有限排队期限由 `timeout_ms` 决定，`SRNOS_WAIT_FOREVER` 时仍采用内部默认 5 ms 排队保护；活动事务期限保持 5 ms。同步有限等待从保留槽位起使用同一个预算，包含 TX 复制、抢占、排队和完成，不因复制阶段被抢占而重新获得一段完整期限。内部用 64 位微秒保存较长有限期限，统计的 32 位排队耗时饱和而不回绕。无限等待仅取消调用者的等待期限，不关闭这些内部保护。有限超时后仍须等待取消确认才返回，因此实际调用时间可以再包含恢复和调度延迟。

异步 `OK` 只表示接纳。回调在分发线程执行，必须短小、不可阻塞；回调上下文和设备必须保留到回调返回。`SRNOS_SPICancel` 为非阻塞接口：`BUSY` 表示相关请求或回调仍拥有缓冲区，调用者必须保留资源并稍后重试；`OK` 才表示取消确认。总线恢复只针对入口观察到的活动请求，保留复制中和排队中的请求；abort 无法确认停止时隔离总线，重启前拒绝新事务。

## 等待与板级边界

分发线程由 Kernel 托管单轮处理，普通等待位于统计边界外。空闲无限等待；活动时等待完成/取消/新请求事件或最近的排队、活动截止点，不再每 tick 唤醒检查。通知在等待入口原子消费，不在检查后额外清除，避免丢失并发完成事件。硬件模式、片选时序、优先级、栈和队列容量保持既有设置。

板级 SPI4 handle、模式与 abort 接入位于 `Board/Support/IO/spi_board`。DMA staging 的位置与大小保持不变，硬件停止确认仍由板级适配负责。

## 验证

`bash Tests/IO/SPI/run_host_tests.sh` 编译实际分发器，覆盖保护外复制抢占、保留槽取消、同步总期限、通知与等待竞争、容量、FIFO/公平性、排队超时、活动取消、恢复隔离及早到/迟到完成中断。当前主机测试通过；它们不能证明板端 DMA/IRQ 延迟、传感器连续性或统计开销，本轮未烧录或重新板测。
