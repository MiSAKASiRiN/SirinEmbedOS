# 固定 SPI4 通路

公开头为 `SirinEmbedOS/IO/SPI/SPI.h`。父项目使用 `SRNOS_*` 传输、取消与快照接口，不需要 HAL、FreeRTOS 或 CMSIS 头。`SRNOS_SPIDevice` 是不透明的 SDK 设备句柄；固定 CS、模式与设备绑定由 Board/设备驱动持有。父项目不能重建 SPI4 或直接控制片选。统计返回调用者拥有的副本。

## 调度与所有权

唯一 `SRNOS_SPI4` 分发线程为 Realtime1（49）/ 3 KiB，负责 HAL、DMA staging、完成复制、回调及恢复；高于 P0 的 CAN1/2/3 与 IMU/INS（48）、P1 的 CAN4/UART（47），及时完成共享总线事务。四个 IMU 槽和四个共享槽固定分配，MCP 使用共享槽并由私有设备标签标识。等待的 IMU 事务优先，最多连续四笔后服务一笔等待的低层请求；低层内 CAN4 优先，最多四笔后服务一笔普通请求，各类 FIFO。正在传输的事务不被抢占；没有运行期分配。

提交方在短临界区保留槽位（`RESERVED`），在保护范围外复制最多 512 B TX，再发布排队状态并通知分发者。复制期间，其他提交不能复用该槽，取消不能提前释放其所有权；`SRNOS_SPIIsBusBusy` 包含这些尚未发布的请求。TX 在提交返回后可以复用，RX 必须保留到完成回调或取消确认。所有传输使用 SDK 非缓存 staging，不公开 Direct 或原始 bus lock 入口。

超时使用 SDK 毫秒和公开头直接提供的 `SRNOS_NO_WAIT` / `SRNOS_WAIT_FOREVER`，有限正值为 `1..INT32_MAX`。所有 SPI DMA 都需分发线程启动，所以显式 `SRNOS_NO_WAIT` 立即返回 `TIMEOUT`，不提交、不等待，也不取得缓冲区所有权。无超时参数的 `TransferAsync` / `TransferDMA` 显式使用默认 5 ms 排队期限，调用本身仍只复制提交，不等待完成。

IMU 排队期限保持 1 ms；普通请求的有限排队期限由 `timeout_ms` 决定，`SRNOS_WAIT_FOREVER` 时仍采用内部默认 5 ms 排队保护；活动事务期限保持 5 ms。同步有限等待从保留槽位起使用同一个预算，包含 TX 复制、抢占、排队和完成，不因复制阶段被抢占而重新获得一段完整期限。内部用 64 位微秒保存较长有限期限，统计的 32 位排队耗时饱和而不回绕。无限等待仅取消调用者的等待期限，不关闭这些内部保护。有限超时后仍须等待取消确认才返回，因此实际调用时间可以再包含恢复和调度延迟。调用者等待期限耗尽记录为 TIMEOUT，显式取消记录为 CANCELLED；取消原因与完成结果在同一短临界区裁定，结果发布前首次记录的取消原因生效，已发布结果不被后来的清理覆盖。TIMEOUT 计入超时统计，两类取消都遵守相同的 RX 释放确认。

异步 `OK` 只表示接纳。回调在分发线程执行，必须短小、不可阻塞；回调上下文和设备必须保留到回调返回。`SRNOS_SPICancel` 为非阻塞接口：`BUSY` 表示相关请求或回调仍拥有缓冲区，调用者必须保留资源并稍后重试；`OK` 才表示取消确认。总线恢复只针对入口观察到的活动请求，保留复制中和排队中的请求；abort 无法确认停止时隔离总线，重启前拒绝新事务。

## 等待与板级边界

分发线程由 Kernel 托管单轮处理，普通等待位于统计边界外。空闲无限等待；活动时等待完成/取消/新请求事件或最近的排队、活动截止点。通知在等待入口原子消费，不在检查后额外清除，避免丢失并发完成事件。硬件模式、片选时序由固定设备声明；优先级和仲裁按上文通信策略配置。

板级 SPI4 handle、模式与 abort 接入位于 `Board/Support/IO/spi_board`。DMA staging 位于非缓存区，硬件停止确认仍由板级适配负责。

## 验证

主机模型不能证明板端 DMA/IRQ 延迟、传感器连续性或统计开销。历史实测范围见 [CHANGELOG](CHANGELOG.md)。

## CAN4 私有事务序列

`SRNOS_SPITransferSequence` 只供设备实现使用：最多四步，每步最多74B，一个共享槽、一次提交、最终一次完成通知，总期限5ms。准备函数只允许有界的寄存器解码和字节准备。每一步结束释放CS，将下一步重新排入原仲裁器；IMU和普通请求仍按原4:1规则获得事务边界，不连续锁住一整条序列。公开 accepted/completed、排队/传输直方图仍按物理事务计数；各步排队耗时从该步入队开始，总期限从首次提交开始。

数据继续经过原非缓存DMA staging。超时/取消返回前确认停止硬件访问；迟到中断不重新完成请求。序列边界、错误、取消和总期限的历史验证范围见 [CHANGELOG](CHANGELOG.md)。

分发线程使用直接任务通知index 0，用于完成/提交唤醒；Kernel控制仍使用index 1。时钟查询复用每轮快照，逐事务期限和超时口径保持。

## 应用观测示例

固定设备 handle 由 SDK 设备层持有；应用通常通过 Sensors 或 CAN 使用 SPI，而不是自行创建片选。下面读取总线统计副本，适合在普通监控任务中调用：

```c
#include "SirinEmbedOS/IO/SPI/SPI.h"
SRNOS_SPIStatus read_spi_status(SRNOS_SPISnapshot *snapshot) {
    return SRNOS_SPIGetSnapshot(SRNOS_SPI_BUS_4, snapshot);
}
```

如需扩展设备，在设备实现中使用已绑定的 handle 调用传输接口，遵守上述缓冲、取消和回调合同；硬件绑定归 Board/Support。
